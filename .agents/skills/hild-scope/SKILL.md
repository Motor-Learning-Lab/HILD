# Scope

Rules: [HILD process](../../../HILD/process.md), *Scope agreements*; format:
[scope-issue template](../../../HILD/templates/scope-issue.md).
Resolve the host's authoritative paths first; `HILD/` is only the default.

1. **Orient.** Read the current plan and relevant decision records; relate the proposed work to a goal. If none fits, make the gap visible.
2. **Resolve the design.** Discuss genuinely open choices with the researcher *before* recording agreement. Say what is in/out, which stopping points are lifted, and what would establish completion. One PR should be explainable in one sitting; split if necessary.
3. **Onboarding only:** if the request is to scope HILD onboarding, read [onboarding-scope.md](onboarding-scope.md) now and adapt its example to this installation. Do not load that companion file for ordinary scopes.
4. **Propose the issue.** Draft it using the canonical template; create it in GitHub as a proposed `scope` issue if the repository and permissions permit, then show the researcher its contents and link. If GitHub is unavailable, present the proposed text without claiming it was created.
5. **Wait for agreement.** Do not begin implementation before the researcher approves the scope. Record approval in the issue before work; if its boundaries change later, propose the amendment and wait instead of silently drifting.

The scope issue is an agreement about *future* work, not evidence that the work is already done. Do not merge a PR or certify human understanding on the researcher's behalf.
