**Findings:**

- **The HILD skills are not native in Claude Code here.** This repository has no `.claude/skills` link, and Git here is set to `core.symlinks=false` at both system and local level. Claude Code on Windows therefore did not offer the `hild-*` skills natively; it read them as ordinary files.
- **The installer's symlink fix covers one clone only.** It suggests `git config --local core.symlinks true`, which leaves a new clone on the same machine at the system default, `false`. This is recorded as an open question on the symlink wiki page.
- **`wiki_status.py --write` produced CRLF line endings on Windows.** It uses `write_text` without `newline`, and Git normalized the endings on commit. Recorded on the platform-independence page, which treats line endings as the host repository's decision: HILD can tolerate them but should not override them.

- **Installed `CLAUDE.md` may not load `AGENTS.md`.** The installer generates `CLAUDE.md` with a plain Markdown link to `AGENTS.md`, not an `@AGENTS.md` import ([L152–156](https://github.com/Motor-Learning-Lab/HILD/blob/938b741d1290248d0e8d78e18071e548e0db2664/HILD/scripts/install_hild.py#L152-L156)), so Claude Code may not load `AGENTS.md` automatically in an installed repository. Scope #19 tests this.
