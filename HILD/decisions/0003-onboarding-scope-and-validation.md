# 0003 — Onboarding is an optional first HILD scope, not a separate skill

**Date:** 2026-10-15 · **Status:** Accepted (reviewed and squash-merged in [PR #5](https://github.com/Motor-Learning-Lab/HILD/pull/5) on 2026-10-16; original agreement in [scope #4](https://github.com/Motor-Learning-Lab/HILD/issues/4))

**Context:** A copied HILD directory is not evidence that agents discover or follow its rules. New adopters also need a useful first experience. A separate onboarding skill or mandatory onboarding on every update would introduce unnecessary machinery and repetition.

**Decision:** The root and installed HILD READMEs invite the user to open a chat with repository access and invoke `hild-scope`. Their suggested first request is **onboarding**, but experienced users may substitute any other development goal. `hild-scope/SKILL.md` refers to a companion `onboarding-scope.md`, loaded when the researcher is new to HILD, asks for guidance getting started, or wants an onboarding scope; `hild-integrate` loads it in the same cases (amended; see below). Onboarding is a normal, reviewed development scope using an issue, early draft PR, real plan/journal updates, and any *genuine* decisions that arise. It may propose a `Process-HILD` understanding-map wiki page that is drafted after merge and confirmed by the human.

**Verification distinction:** Every installation/update receives mechanical installation-integrity checks; those checks do not demonstrate behavioral compliance. The interactive onboarding cycle is **recommended but optional** for users. It is part of HILD's *first* complete installer acceptance test and is repeated selectively for major changes to the process or agent machinery, **not for every HILD update**. Evidence must distinguish passed, failed, pending, inapplicable and untested capabilities.

**Why:** The learner experiences the real process while creating useful, durable project artifacts. There is a single scoping entry point, not competing procedures; validation investment follows changes that actually warrant it.

**Consequences:** The scoping skill needs only one optional companion file, which `hild-integrate` also uses rather than keeping its own newcomer guidance. Onboarding validation cannot be claimed before the real human-agent cycle and post-merge orientation finish. A wiki page cannot be recorded as complete just because it was proposed in the PR.

**Amendment, 2026-11-22 ([PR #32](https://github.com/Motor-Learning-Lab/HILD/pull/32)):** this record originally said the companion was loaded "**only** for an onboarding request" from `hild-scope`. In the first `hild-integrate` test, the agent overwhelmed a new researcher with technical detail before explaining how HILD could help them ([decision 0005](0005-conversational-scope-building.md), *Context*). So [PR #8](https://github.com/Motor-Learning-Lab/HILD/pull/8), reviewed and merged by the researcher, widened when it is loaded and had `hild-integrate` load it too; decision 0005 records that change. The [process](../process.md#develop-scopes-through-dialogue) and the [scope skill](../../.agents/skills/hild-scope/SKILL.md) followed PR #8, but this record was not updated. The [scope #18 audit](https://github.com/Motor-Learning-Lab/HILD/issues/18) found the mismatch, and the researcher chose to align this record with the approved behavior rather than narrow the skill.
