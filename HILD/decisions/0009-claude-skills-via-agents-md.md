# 0009 — Claude Code finds HILD's skills through AGENTS.md, not a symlink

**Date:** 2026-11-21 · **Status:** Proposed (accepted only if the researcher approves the pull request that adds it)

**Relationship to earlier decisions:** Modifies [Decision 0004](0004-selectable-agent-integrations.md): one provision only, how Claude Code is pointed at the shared skills. One shared set of skills in `.agents/skills/`, selectable agents and the recorded installation metadata stay as 0004 says.

**Context:** Codex and Copilot read `.agents/skills/` directly. Claude Code reads skills only from `.claude/skills/` and loads other files only through `@path` imports. The installer therefore created the symlink `.claude/skills -> ../.agents/skills`. In the Windows pilots ([2026-10-28 journal](../journal/2026-10-28.md), [scope #4 findings](https://github.com/Motor-Learning-Lab/HILD/issues/4#issuecomment-6253200260)) that link was fragile: with `core.symlinks=false`, Git checks a committed link out as a plain text file, even when the first install succeeded. The installer answered with a refusal and checks tied to Git's setting. The generated `CLAUDE.md` also only linked to `AGENTS.md`, which Claude Code does not load. [Scope #19](https://github.com/Motor-Learning-Lab/HILD/issues/19) compared the arrangements in headless Claude Code runs ([results](https://github.com/Motor-Learning-Lab/HILD/issues/19#issuecomment-6746746079), [confirmation runs](https://github.com/Motor-Learning-Lab/HILD/issues/19#issuecomment-6748912826)). Without the link, but with `CLAUDE.md` importing `@AGENTS.md` and a skills index in `AGENTS.md`, Claude read the expected skill in at least as many runs as with the link, and stopped before acting in every run.

**Decision:** The installer no longer creates `.claude/skills`. The generated `CLAUDE.md` imports `@AGENTS.md`. The generated `AGENTS.md` has a "HILD skills" index: one line per skill with its path and its frontmatter description, built at install time. `--verify` checks the import and that every indexed skill exists. The installer's `core.symlinks` refusal and checks are removed. This repository's own `AGENTS.md` carries the same kind of index, and the session-start hook orients briefly without replacing a different first request.

**Why:** The index works as well in the measured runs, needs no OS or Git setting, avoids a second location that can silently break, and fixes the unloaded `AGENTS.md`. Alternatives considered: (1) **keep the link**: native slash-command skills, but it fails on Windows without `core.symlinks=true` and the installer must police Git's configuration; (2) **copy the skills into `.claude/skills`**: no symlink problem, but a second copy of every skill that can drift, which 0004 rules out.

**Consequences:** Claude Code no longer discovers HILD's skills natively: no skill descriptions loaded up front and no native `/hild-scope` expansion. In the scope #19 runs `/hild-scope` still worked, because Claude saw the name in the index and read the file, but that is the agent following instructions, not the harness loading a skill. A user who wants native discovery can add the link themselves; HILD will not create it or check for it. Updated alongside: [agent-setup](../agent-setup.md), [onboarding test protocol](../onboarding-test-protocol.md), the [first-install procedure](../../.agents/skills/hild-integrate/first-install.md), and the installer and its tests.

**Validation:** Scope #19's headless runs are evidence for the arrangement, not for a full onboarding. The [scope #12](https://github.com/Motor-Learning-Lab/HILD/issues/12) onboarding test is the real check, on Windows with Claude Code; until it passes, native-quality discovery is not established. The installer's tests and CI check the files, not the agent's behavior.
